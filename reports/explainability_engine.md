# Explainability Engine for Thirukkural Scenario-Based Decision-Making System

## Overview

The Explainability Engine transforms raw prediction outputs from the inference engine into structured, human-readable explanations that help users understand the ethical reasoning behind the system's decisions. This component is designed to be fully deterministic and transparent, relying solely on the retrieved knowledge object and retrieval metadata—no machine learning or external APIs are used for explanation generation.

## Architecture

The explainability module consists of two primary components:

1. **`Explanation` dataclass** (`src/explanation.py`): Defines the structure of an explanation object with fields for all relevant information.
2. **`ExplainabilityEngine` class** (`src/explainability.py`): Processes `Prediction` objects from the inference engine and generates `Explanation` objects.

### Data Flow

```
Input Image
      │
      ▼
Inference Engine  →  Prediction Object
      │
      ▼
Explainability Engine  →  Explanation Object
      │
      ▼
Formatted Explanation (Optional)
```

## Input

The explainability engine accepts a `Prediction` object generated by the inference engine (`src/inference.py`). This object contains:

- Matched scenario ID and Thirukkural number
- Ethical concept, chapter (adhigaram), and section (paal)
- Scenario description, question, correct answer, and explanation
- Similarity scores (image, knowledge, combined)
- Confidence score
- Top-K alternative matches

## Output

The engine produces an `Explanation` object with the following structure:

```python
@dataclass
class Explanation:
    prediction_summary: str
    matched_concept: str
    matched_kural: str
    matched_scenario: str
    scenario_description: str
    question: str
    correct_answer: str
    ethical_reasoning: str
    confidence_level: str
    confidence_value: float
    retrieval_scores: Dict[str, float]
    alternatives: List[Dict[str, Any]]
```

### Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `prediction_summary` | str | Natural language summary of the prediction (e.g., "The uploaded image most closely matches Scenario S042, representing the concept of Compassion. Therefore, the system retrieved Thirukkural 42.") |
| `matched_concept` | str | The ethical concept identified, enriched with chapter and section information (e.g., "Compassion under Chapter 4 (Aram)") |
| `matched_kural` | str | The Thirukkural number as a string (e.g., "42") |
| `matched_scenario` | str | The scenario ID of the matched result (e.g., "S042") |
| `scenario_description` | str | The full textual description of the matched scenario |
| `question` | str | The ethical question associated with the scenario |
| `correct_answer` | str | The correct answer option (A, B, C, or D) for the scenario |
| `ethical_reasoning` | str | The detailed explanation from the Thirukkural justifying the correct answer |
| `confidence_level` | str | Categorized confidence: "Very High", "High", "Moderate", or "Low" |
| `confidence_value` | float | Numerical confidence score (0-1) rounded to configured precision |
| `retrieval_scores` | dict | Dictionary containing `image_similarity`, `knowledge_similarity`, and `combined_score` (each rounded) |
| `alternatives` | list | List of alternative matches considered, each containing `scenario_id`, `concept`, `combined_score`, and `english_kural` |

## Configuration

The explainability behavior is configured through `config/config.py` with the following parameters:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `EXPLAINABILITY_DECIMAL_PRECISION` | int | 3 | Number of decimal places for rounding similarity scores |
| `EXPLAINABILITY_NUM_ALTERNATIVE_MATCHES` | int | 3 | Number of alternative matches to include in the explanation |
| `CONFIDENCE_VERY_HIGH_THRESHOLD` | float | 0.90 | Minimum score for "Very High" confidence |
| `CONFIDENCE_HIGH_THRESHOLD` | float | 0.75 | Minimum score for "High" confidence |
| `CONFIDENCE_MODERATE_THRESHOLD` | float | 0.60 | Minimum score for "Moderate" confidence |

## Explanation Generation Process

1. **Confidence Categorization**: The numerical confidence score is mapped to a qualitative level using predefined thresholds.
2. **Score Rounding**: All similarity scores (image, knowledge, combined) are rounded to the configured decimal precision.
3. **Concept Formatting**: The ethical concept string is constructed by combining the concept name with its associated chapter (adhigaram) and section (paal) when available.
4. **Summary Generation**: A natural language summary is created identifying the matched scenario, concept, and Thirukkural number.
5. **Alternative Extraction**: Top-K alternative matches (excluding the primary result) are extracted from the prediction's top-matches list.
6. **Object Construction**: An `Explanation` object is populated with all the above components.

## Usage Example

```python
from src.inference import InferenceEngine
from src.explainability import ExplainabilityEngine

# Initialize and load the inference engine (once)
engine = InferenceEngine()
engine.load()

# Make a prediction
prediction = engine.predict("path/to/image.jpg")

# Generate explanation
explainer = ExplainabilityEngine()
explanation = explainer.generate_explanation(prediction)

# Access explanation components
print(explanation.prediction_summary)
print(explanation.matched_concept)
print(explanation.ethical_reasoning)
print(f"Confidence: {explanation.confidence_level} ({explanation.confidence_value})")
print("Alternatives:")
for alt in explanation.alternatives:
    print(f"  - Scenario {alt['scenario_id']}: {alt['concept']} (score: {alt['combined_score']})")

# Optional: Get formatted string explanation
formatted = explainer.format_explanation(explanation)
print(formatted)
```

## Format Method

For console display or logging, the `format_explanation` method converts an `Explanation` object into a human-readable multi-line string with clear section headers and formatting.

## Deterministic Guarantee

The explainability engine is completely deterministic:
- Given the same `Prediction` input, it will always produce identical `Explanation` output
- No randomness, external calls, or model inference is involved
- Output depends solely on the input prediction object and configuration values

## Limitations

- Explanations are constrained to the information present in the knowledge object and retrieval scores
- The explanation text for the ethical reasoning is directly copied from the dataset; no rephrasing or simplification is performed
- Alternative matches are limited to those already retrieved by the inference engine (top-K results)

## Future Extensions

While the current implementation is strictly deterministic and dataset-driven, the architecture is designed to allow future enhancements:
- The explanation text generation could optionally be replaced with an LLM-based natural language generator while preserving the same structural output
- Additional metadata (same explanation object format)
- The core retrieval and scoring logic remains untouched, ensuring backward compatibility

## Conclusion

The explainability bridge provides transparent, audit-ready insights into the Thirukkural retrieval system's decision-making process. By exposing the reasoning behind each prediction in a structured format, it enables educational use cases, debugging, and trust-building with end-users who need to understand not just what the system decided, but why.
